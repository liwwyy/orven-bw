# Validation (2026-10-01)

## Build and tests

A clean build succeeded with **Gradle 9.8.0 / Temurin JDK 27**, targeting **Java 25**.
The generated class files have major version 69. The Gradle distribution checksum
is pinned, and the wrapper scripts/jar were regenerated by Gradle 9.8.0.

```sh
JAVA_HOME=/usr/lib/jvm/java-27-temurin ./gradlew clean build
```

Deleting the extracted OneConfig beta API directory and rebuilding successfully
recreated it from the installed modpack jar. Its dependency collection carries
`builtBy(prepareOneConfig)`, including for source remapping.

Nine deterministic JUnit tests pass:

- Strict physical CPS activation and delayed dispatch.
- Rolling cap with physical input preserved.
- Pending-click budget and cap changes.
- Independent one-second expiration of physical and boosted input.
- Cancellation when eligibility disappears.
- Dropping expired work after a stall.
- Zero chance and probability-boundary behavior.
- Left/right channel separation and resetting.
- No further clicks without new physical input.

Test reports: `build/reports/tests/test/index.html`.
Artifacts: `build/libs/orven-bw-0.1.0+mc1.8.9.jar` and its `-sources.jar` counterpart.
The mod jar contains only this mod's classes/resources, not OneConfig or reference code.
Its manifest reports `Calamus-Generation: 2` and `Fabric-Mapping-Namespace: intermediary`.

## Isolated beta startup

A read-only set of references to the installed OneClient beta mods was launched
under Java 25 with an offline test identity and an Xvfb virtual display. Generated
config, logs, caches and crash reports stayed under ignored `.reference/smoke/`.
The original Prism instance was not launched, configured or modified.

Confirmed from actual runtime evidence:

- Fabric Loader 0.19.5 discovered `orven-bw 0.1.0+mc1.8.9`.
- The client entrypoint logged `orven-bw initialized`.
- OneConfig saved `config/orven-bw.json` with all expected settings/defaults.
- Minecraft's exported transformed bytecode contains all four applied handlers:
  `orven$checkContext`, `orven$mousePress`, `orven$keyboardPress`, and
  `orven$beforeInteractions`. Required injectors resolved against the pack's actual
  Minecraft class alongside its existing mods.

Full gameplay and visual HUD testing could not be completed here: Pylon 0.1.7's
SDL VSync operation throws `IllegalStateException: That operation is not supported`
under the virtual display during game initialization. Disabling VSync in the isolated
options did not avoid this external graphics failure. A smaller dependency launch
confirmed that the OneConfig 1.2.9 platform **requires Pylon >=0.1.7**, so it cannot
simply be omitted to bypass that limit. The full pack also logs Flap setup errors
with its existing mod remapping cache. None of those external mods were patched.

The remaining manual check is to install the built jar into the real beta instance,
add the HUD from the OneConfig editor, enable ClickAssist and test physical clicking
in a world. Verify creative/weapon/target/block gates, a second player at four blocks,
right-click assistance, remapped bindings, and resets on menus and world changes.
Expected HUD behavior: base CPS remains independent of generated clicks; both
histories expire after one second; holding alone never boosts.
